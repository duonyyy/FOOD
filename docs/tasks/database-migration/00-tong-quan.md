# Tổng quan: PostgreSQL chưa được chạy migration

## Trạng thái

- **Mức độ:** P0 — chặn các API đọc dữ liệu chính.
- **Trạng thái:** Chưa xử lý.
- **Phạm vi:** Khởi tạo schema PostgreSQL, chạy TypeORM migration và kiểm thử API.
- **Không phải nguyên nhân:** MinIO. MinIO đã kết nối, tạo bucket và upload/delete thành công.

## Vấn đề đang gặp

Các API sau đang trả HTTP `500`:

```text
GET /restaurants/all?page=1&pageSize=1
GET /foods?page=1&pageSize=1
GET /promotions/all?page=1&pageSize=1
```

Lỗi trong log API:

```text
QueryFailedError: relation "restaurants" does not exist
QueryFailedError: relation "foods" does not exist
QueryFailedError: relation "promotions" does not exist
```

## Hiện trạng database đã xác minh

Database đang được dùng bởi container `fooddie_db`:

```text
database: fooddie_db
user: postgres
application tables: 0
migrations table: chưa tồn tại
pending migrations: 23
```

Các migration có trong source nằm tại:

```text
foodee-be/src/migrations/
```

Migration đầu tiên tạo bảng nền là:

```text
src/migrations/1700000000000-AutoGeneratedMigration.ts
```

Migration cuối cùng hiện có là:

```text
src/migrations/1750000000024-AddTenRestaurantsWithFoodsAndToppings.ts
```

## Nguyên nhân gốc

### 1. Runtime không tự chạy migration

File:

```text
src/infra/database/database.module.ts
```

Cấu hình hiện tại:

```typescript
synchronize: false,
migrationsRun: false,
```

Điều này an toàn cho production nhưng yêu cầu phải có một bước migration riêng trước khi API truy cập các bảng.

### 2. Docker Compose chỉ chờ PostgreSQL healthy

File:

```text
docker-compose.yml
```

`api` hiện chỉ phụ thuộc vào trạng thái health của `postgres`, `redis`, `ai-server` và `minio`. PostgreSQL healthy chỉ có nghĩa là server nhận kết nối; nó không có nghĩa là schema đã được tạo.

### 3. Migration command hiện tại phụ thuộc vào dev dependency

File:

```text
package.json
```

Các script hiện tại dùng `ts-node` và file TypeScript trong `src/config/typeorm.data-source.ts`.

Trong production image:

```text
Dockerfile:32-36
```

image chạy `npm ci --omit=dev`, nên không có `ts-node`. Tuy nhiên image vẫn có:

```text
/app/dist/config/typeorm.data-source.js
/app/dist/migrations/*.js
/app/node_modules/typeorm
```

Vì vậy cần thêm compiled migration command chạy trực tiếp bằng Node.

## Các file liên quan

| Khu vực | File | Vai trò |
|---|---|---|
| Runtime DB | `src/infra/database/database.module.ts` | Cấu hình kết nối TypeORM cho NestJS |
| CLI DB | `src/config/typeorm.data-source.ts` | DataSource cho TypeORM CLI |
| Scripts | `package.json` | Các lệnh migration hiện có |
| Docker | `Dockerfile` | Build `dist`, loại bỏ dev dependency trong production |
| Orchestration | `docker-compose.yml` | Khởi động PostgreSQL và API |
| Schema | `src/migrations/` | 23 migration tạo schema và seed data |
| API lỗi | `src/modules/restaurant/restaurant.service.ts` | Query bảng `restaurants` |
| API lỗi | `src/modules/food/food.service.ts` | Query bảng `foods` |
| API lỗi | `src/modules/promotion/promotion.service.ts` | Query bảng `promotions` |

## Giải pháp được khuyến nghị

Tạo một service `migrate` chạy một lần trước API:

```text
PostgreSQL healthy
        ↓
migrate chạy toàn bộ TypeORM migration
        ↓
migrate completed successfully
        ↓
API được phép khởi động
```

Không nên bật `synchronize: true`. Cũng không nên chỉ bật `migrationsRun: true` trên mọi API replica vì nhiều instance có thể cùng cố gắng chạy migration.

## Definition of Done

- Database mới chạy được toàn bộ 23 migration.
- Bảng `migrations` được tạo và ghi nhận đủ migration đã chạy.
- Các bảng `restaurants`, `foods`, `promotions` tồn tại.
- API không còn lỗi `relation does not exist`.
- Ba endpoint đọc dữ liệu trả HTTP `200`.
- `docker compose up` tự chạy migration trước API.
- Chạy lại migration không tạo dữ liệu trùng hoặc lỗi.
- CI có test database rỗng từ đầu.
